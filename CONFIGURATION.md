## 📋 Backend Configuration

### Required Environment Variables

#### `DATABASE_URL` ⭐ REQUIRED
- **Type**: Connection string (not an API key)
- **Purpose**: PostgreSQL database connection
- **Format**: `postgresql://username:password@host:port/database_name`
- **Example**: `postgresql://admin:secret123@localhost:5432/marketplace_db`
- **Where to get**: Your PostgreSQL provider (Railway, Render, Supabase, Neon, or self-hosted)
- **Validation**: Must start with `postgresql://` or `postgresql+psycopg2://`
- **Error if missing**: Application will fail to start

#### `SECRET_KEY` ⭐ REQUIRED
- **Type**: Secret string (internally generated, NOT an external API key)
- **Purpose**: Signing JWT authentication tokens
- **Requirements**: Minimum 32 characters
- **How to generate**:
  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```
- **Example**: `aB3dEf9hIjKlMnOpQrStUvWxYz1234567890AbCdEfGhIjKlMnOpQrStUvWxYz`
- **Security**: Keep this secret! Do not commit to version control
- **Validation**: Must be at least 32 characters
- **Error if missing/invalid**: Application will fail to start

### Optional Environment Variables (Have Defaults)

#### `ALGORITHM`
- **Type**: String
- **Default**: `HS256`
- **Purpose**: JWT signing algorithm
- **Options**: `HS256`, `HS384`, `HS512`
- **When to change**: Only if you need a different algorithm

#### `ACCESS_TOKEN_EXPIRE_MINUTES`
- **Type**: Integer
- **Default**: `30`
- **Purpose**: JWT token expiration time in minutes
- **Range**: 1-1440 (1 minute to 24 hours)
- **When to change**: Adjust based on security requirements

#### `CORS_ORIGINS`
- **Type**: Comma-separated list of URLs
- **Default**: `http://localhost:3000,http://localhost:3001`
- **Purpose**: Allowed frontend origins for CORS
- **Format**: `http://localhost:3000,https://yourdomain.com`
- **When to change**: Set to your production frontend URL(s)

#### `LOG_LEVEL`
- **Type**: String
- **Default**: `INFO`
- **Purpose**: Logging verbosity
- **Options**: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`
- **When to change**: Use `DEBUG` for development, `INFO` for production

#### `ENVIRONMENT`
- **Type**: String
- **Default**: Not set (development mode)
- **Purpose**: Environment identifier
- **Options**: `development`, `production`, `staging`
- **When to change**: Set to `production` in production deployments

#### `AI_BATCH_JOB_TIMEOUT_HOURS`
- **Type**: Integer
- **Default**: `2`
- **Purpose**: Hours before AI batch job is considered stale
- **When to change**: Adjust if jobs take longer than 2 hours

## 🎨 Frontend Configuration

#### `NEXT_PUBLIC_API_URL` ⭐ REQUIRED

## 🔒 Security & Secrets

### Understanding Configuration Types

#### 1. Secrets (Internal)
- **SECRET_KEY**: Generated by you, stored securely
- **Purpose**: Internal application security
- **NOT an API key**: This is your own secret, not from a third party
- **Storage**: Environment variables, never in code

#### 2. Connection Strings (Your Infrastructure)
- **DATABASE_URL**: Your database connection info
- **Purpose**: Connect to your own database
- **NOT an API key**: Just connection credentials for your own infrastructure
- **Storage**: Environment variables

#### 3. URLs (Your Infrastructure)
- **NEXT_PUBLIC_API_URL**: Your backend URL
- **Purpose**: Frontend-to-backend communication
- **NOT an API key**: Just a URL pointing to your own server
- **Storage**: Environment variables

### Security Best Practices

1. **Never commit secrets to version control**
   - Use `.env` files (already in `.gitignore`)
   - Use environment variables in production

2. **Generate strong SECRET_KEY**
   - Use the provided Python command
   - Minimum 32 characters
   - Use cryptographically secure random generation

3. **Rotate SECRET_KEY if compromised**
   - All existing JWT tokens will become invalid
   - Users will need to log in again

4. **Protect DATABASE_URL**
   - Contains database credentials
   - Restrict access to production environment variables
   - Use connection pooling in production

## ✅ Configuration Validation

### Backend Validation

The application validates configuration at startup:

1. **Required Variables**
   - `DATABASE_URL`: Must be present and valid PostgreSQL URL
   - `SECRET_KEY`: Must be present and at least 32 characters

2. **Validation Behavior**
   - **Production**: Fails fast with clear error message if invalid
   - **Development**: Warns but allows defaults (for easier local setup)

3. **Error Messages**
   - Clear, actionable error messages
   - Tells you exactly what's wrong and how to fix it

### Example Validation Errors

```
Error: SECRET_KEY must be at least 32 characters long
Fix: Generate a new key using: python -c "import secrets; print(secrets.token_urlsafe(32))"

Error: DATABASE_URL must be a PostgreSQL connection string
Fix: Ensure DATABASE_URL starts with postgresql://
```

## 📝 Setup Examples

### Development Setup

**Backend `.env`**:
```bash
DATABASE_URL=postgresql://user:password@localhost:5432/marketplace_db
SECRET_KEY=dev-secret-key-minimum-32-characters-long-change-in-production
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
CORS_ORIGINS=http://localhost:3000
LOG_LEVEL=DEBUG
```

**Frontend `.env.local`**:
```bash
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### Production Setup

**Backend Environment Variables** (set in hosting platform):
```bash
DATABASE_URL=postgresql://user:password@prod-db.example.com:5432/marketplace
SECRET_KEY=<generated-64-character-secret-key>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
CORS_ORIGINS=https://yourdomain.com
LOG_LEVEL=INFO
ENVIRONMENT=production
```

**Frontend Environment Variables** (set in Vercel/Netlify):
```bash
NEXT_PUBLIC_API_URL=https://api.yourdomain.com
```
